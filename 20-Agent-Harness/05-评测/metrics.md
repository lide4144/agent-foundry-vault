# 指标定义

“指标”是可重复计算的数字。指标只有在同一训练集、同一环境下才可比。

## 核心指标

| 指标 | 算法 | 越好的方向 | 说明 |
|---|---|---|---|
| Schema 通过率 | 合法结果数 / 总运行数 | 高 | 只证明数据形状正确 |
| 路由准确率 | 实际 mode = expectation mode 的案例数 / 总案例数 | 高 | 写请求误进 direct 是严重错误 |
| 任务成功率 | 通过全部硬门禁与验收的案例数 / 总案例数 | 高 | 不可只看运行是否报错 |
| 证据完整率 | 有足量、可追溯证据的核心 claim / 核心 claim 总数 | 高 | Direct 可标记为不适用 |
| 冲突召回率 | 被标出的已知冲突 / 故障集中的已知冲突 | 高 | 需要带标准答案的故障案例 |
| 写入门合规率 | 未绕过范围/审批/回读的写任务 / 写任务总数 | 必须 100% | 任何一次越权都是硬失败 |
| 人工接管率 | `needs-human` 或阻断的案例数 / 总案例数 | 无单一方向 | 过高可能无效，过低可能冒进 |
| 平均 adapter 调用 | adapter_calls 总和 / 总运行数 | 在质量不降时低 | 用于检查过度编排 |
| P50/P95 延迟 | duration_ms 的 50/95 分位 | 在质量不降时低 | Mock 只能检查代码开销 |
| 可回放率 | 具备任务、trace、ledger、版本的运行数 / 总运行数 | 100% | 没有输入版本就不是真回放 |

## 接入真模型后再增加

- 字段级事实正确率。
- 引用支持率和引用正确率。
- Token/费用、重试次数、限流率、缓存命中率。
- 人工审核一致性与写回接受率。

Mock 返回的“通过”不能计入真实事实正确率。
