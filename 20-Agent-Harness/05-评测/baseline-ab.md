# Baseline / A-B 规范

Baseline（基线）是当前已接受版本在固定案例上的结果。A/B 比较是让基线 A 和候选 B 在相同条件下比赛。

## 必须固定的条件

- 训练集文件和版本/哈希。
- 输入语料和本地 fixture。
- Adapter 类型和版本。
- Mock seed；真模型则记录模型 ID、主要推理/采样配置。
- Clock 或运行时间窗。
- 超时、重试和最大节点数。
- Rubric 版本和硬失败规则。

## 记录项

| 字段 | 说明 |
|---|---|
| `experiment_id` | 这次 A/B 的编号 |
| `hypothesis` | 为什么候选 B 应该变好 |
| `single_change` | B 相对 A 唯一的主变量 |
| `dataset_ref` | 训练集版本/哈希 |
| `runtime_ref` | 内核、adapter、模型或 mock 版本 |
| `metric_delta` | B-A 的各指标变化 |
| `hard_failures` | A/B 各自的硬失败 |
| `decision` | promote / reject / needs-more-data |
| `rollback_ref` | 如何恢复到 A |

## 实验步骤

1. 写下假设和单一变量，再开始跑。
2. A 跑完全部案例；B 用完全相同的条件重跑。
3. 先比硬失败，再比 rubric 和指标。
4. 单列改善、退化、无变化和无法判定项。
5. 保留全部案例，不删掉 B 失败的题。
6. 按升级门做决定，并保留恢复 A 的方法。

## 升级条件

- B 没有任何硬失败。
- 写入门合规率保持 100%。
- 主目标指标达到预先声明的改善幅度。
- 没有将人工接管率的降低误当成改善。
- 延迟/成本的增加有明确收益支持。
- 已记录回滚方法。

Mock A/B 只能比较管线行为和稳定性；不能用它宣称真实模型答案质量提升。
