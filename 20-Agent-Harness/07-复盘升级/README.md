# 复盘与升级

复盘不是让 Agent 写一段“下次会更好”。它要把失败变成可回放案例，再用 A/B 证明修改有效。

## 失败分类

| 类型 | 例子 | 优先检查 |
|---|---|---|
| 协议失败 | 缺必填字段、ID 不一致 | Schema 与输出组装 |
| 路由失败 | 写任务进了 direct | Router 规则与任务 envelope |
| 证据失败 | 单源写成多源确认 | Worker/Reviewer 与 ledger |
| 工具失败 | 超时、限流、返回形状变化 | Adapter 和故障降级 |
| 安全失败 | 绕审批、超路径写入 | 权限策略与写入门 |
| 质量失败 | 合 Schema 但答非所问 | 验收标准、真模型输出与 rubric |

## 一份合格复盘

1. **症状**：用 result/trace/ledger 的具体字段描述。
2. **影响**：哪些案例、用户或数据受影响。
3. **直接原因**：哪个节点首先违反了什么契约。
4. **系统原因**：为什么现有校验或评测没有更早拦住。
5. **回放案例**：将失败缩成无秘密、可离线复现的候选案例。
6. **单一修改**：每次只更改一个主变量。
7. **验证证据**：记录 A/B 结果、硬门禁、退化和回滚点。

## 升级规则

- 失败案例先加入候选集，证明可稳定复现后才进基准集。
- 修复必须重跑全部安全回归，不只重跑失败的那一题。
- 约束越多不等于越好；新规则如让正常案例大量误拦，应拒绝。
- Prompt、路由、Schema、adapter 和评测集都应有版本和回滚点。
- 自动复盘只能生成候选建议，不得自动修改生产规则或正式知识。

## 什么时候不升级

- 只有 mock 管线证据，却声称真模型质量提升。
- 实验时改了多个主变量，无法判断作用来源。
- 候选版有新的安全硬失败。
- 缺少数据、人工裁决或真实环境验证。
