# 训练闭环：从案例到可验证升级

这里的“训练”是训练 harness 和工作流，不是在本地训练大模型权重。

## 闭环

```text
固定案例 → 基线运行 → 收集 result/trace/ledger
        → rubric 评分 → 定位失败类型
        → 一次只改一个变量 → A/B 回放
        → 通过升级门 → 记录版本与回滚点
```

## 七步做法

1. 从 `seed-cases.jsonl` 选定固定案例，不在跑完后改标准。
2. 固定 adapter、seed、clock 和输入语料。
3. 运行当前版本 A，保存基线指标。
4. 只改一个变量得到候选版本 B。
5. 用同一批案例回放 B，检查硬失败和指标退化。
6. 只有安全门全通过、主指标改善且无重要退化时才升级。
7. 记录改了什么、为什么、用哪些案例验证和怎样回滚。

## 禁止的假闭环

- 只看一个成功示例就声称升级成功。
- 边跑边改案例或评分标准。
- 让 Agent 根据自己一次的 trace 直接修改生产规则。
- 只比较输出文风，不比较路由、证据、安全和人工接管。
- 把 deterministic mock 的通过率当成真实模型质量。
