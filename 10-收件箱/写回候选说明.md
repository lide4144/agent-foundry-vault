# 写回候选说明

“候选”表示尚未成为正式知识。这里是 Agent 输出与主知识库之间的缓冲区。

## 何时用

- Agent 建议新增或修改正式知识页。
- 多个来源给出不同结论。
- 想修正 `raw/` 里看到的问题。
- 一项改动会影响链接、索引或日志。

## 三步操作

1. 写清目标文件、建议内容、来源与已知冲突；不要直接改目标。
2. 按 [[30-系统工具库/SOP/安全写回SOP]] 检查规则、备份和差异。
3. 经人工确认后再写入允许修改的位置，并维护对应 `index` 与 `log`。

## 候选记录最少要回答

- 想改哪一篇？
- 为什么要改？
- 哪些来源支持？
- 是否存在反对证据或同名异实体？
- 改动前后有什么差异？
- 谁确认了写回？

这些审核信息写在候选正文中；不要扩充首周 Frontmatter 字段。

## 不可越过的边界

- `raw/` 只读；只能引用、映射或另写更正说明。
- 冲突不得静默覆盖，必须保留双方来源和采纳理由。
- 未通过审核的 Agent 输出不能进入正式知识页。
- 不得绕过仓库局部规则；局部规则与通用说明冲突时，以局部规则为准。

## 完成标准

- [ ] 目标、来源、冲突和差异都可见。
- [ ] 已确认目标位置允许写入。
- [ ] 写回后已检查链接，并维护 `index` 与 `log`。
- [ ] 可以说明如何回滚。

## 常见错误

- 只保留最终结论，不保留冲突证据。
- 把候选文件改名成“已确认”却没有人工确认记录。
- 为修复总结而改写原始素材。
- 写回正文后忘记维护索引和操作记录。
