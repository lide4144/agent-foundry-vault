# LLMWiki 目录兼容说明

本仓保留 LLMWiki 使用的五个目录名，并把它们放在 Vault 根目录。不要把它们移动到 `40-Wiki知识库/` 下面，也不要随意翻译或改名。

## 何时用

- 配置或检查 LLMWiki 的读取范围。
- 搬迁知识条目或调整目录时。
- 不确定哪个目录是人类说明、哪个目录是正式数据时。

## 三步操作

1. 确认 Vault 根目录存在 `raw/ concepts/ entities/ comparisons/ queries/`。
2. 确认 `40-Wiki知识库/` 只承担中文说明和导航，不替代五个数据目录。
3. 只使用已经验证的 LLMWiki 索引或重建流程；当前仓库没有明确流程时，停下询问，不猜命令。

## 五个目录的职责

| 目录 | 角色 | 写入规则 |
|---|---|---|
| `raw/` | 原始来源、溯源材料 | 只读；不由 Agent 原地改写 |
| `concepts/` | 概念、定义、原理 | 审核后写入 |
| `entities/` | 具体对象与实体档案 | 审核后写入，先做实体消歧 |
| `comparisons/` | 对比、冲突、方案权衡 | 保留双方来源与采纳理由 |
| `queries/` | 查询记录、证据和候选结论 | 可作为写回候选来源，不等于已确认知识 |

## 数据边界

- Obsidian 中审核过的 Markdown 是人类可维护知识源。
- LLMWiki 的索引、向量或缓存是可重建派生物，不应成为唯一真相。
- Agent 的 trace、置信度、token、冲突集合等机器字段留在后台，不加入首周五字段。
- 正式知识变更必须维护相应 `index` 与 `log`；两者的具体位置以仓库局部规则为准。

## 完成标准

- [ ] 五个目录位于 Vault 根目录且名称未改变。
- [ ] `raw/` 保持只读。
- [ ] 人类知识源与派生索引可区分。
- [ ] 没有使用未经验证的重建命令。

## 常见错误

- 为了中文化把 `concepts/` 改成其他名称。
- 把向量索引复制进普通笔记区。
- 索引失败时直接删除知识源重来。
- 未确认工具版本就照搬网络命令。
