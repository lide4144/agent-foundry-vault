# 创意库

这里保存虚构项目的灵感、世界观、角色、源文件、对话调试和发布记录。第一次使用时，复制“示例项目-雨夜便利店”的结构即可，不必先学完整 JSON 格式。

## 何时用

- 想把一个角色、场景或世界设定发展成可测试项目时。
- 准备制作 SillyTavern 角色卡、世界书或配套脚本时。
- 需要记录真实导入测试、回归结果和发布版本时。

## 三步操作

1. 在“01-灵感”写一句可理解的点子，再让世界观和角色互相补全。
2. 把确认后的内容写进“04-源文件”；源文件是唯一真源，JSON、PNG 和压缩包只是派生物。
3. 在“05-对话调试”记录真实测试；只有目标环境导入回归通过后，才能进入“06-发布”。

## 推荐路径

~~~text
灵感 → 世界观 ↔ 角色 → 源文件 → 对话调试 → 发布
~~~

“世界观 ↔ 角色”是双向迭代，不要求先写完整世界再写角色。改了角色经历，要回看世界规则；改了世界规则，也要回看角色是否仍成立。

## Source-first 规则

- Markdown、YAML 或项目约定的结构化源文件是唯一真源。
- 导出的角色卡 JSON、世界书 JSON、PNG 卡图和 ZIP 不手工反向修改。
- 导出格式由项目 manifest 指定的目标 SillyTavern 与扩展版本决定，不在全仓写死某个卡片版本。
- 若必须从已发布文件回收修复，先把变化还原到源文件，再重新导出。

## SillyTavern 生态分层

| 层 | 负责 | 不要混淆 |
|---|---|---|
| SillyTavern Core | 角色、聊天、世界书、预设、宏、事件和导入导出宿主 | 不等于 Tavern Helper、EJS 或 MVU |
| Tavern Helper / JS-Slash-Runner | iframe 前端、脚本与较高层辅助接口 | 属于可选扩展，不能假设所有用户已安装 |
| ST-Prompt-Template / EJS | 在生成或渲染阶段处理明确的模板逻辑 | 不是通用脚本宿主，也不应藏不可审计推理 |
| MVU / MagVarUpdate | 维护消息楼层中的结构化 stat_data，并按其协议更新 | 是独立可选层，不是角色卡和世界书的必备字段 |

项目只使用实际需要的层，并在 manifest 中写明目标版本。没有安装或没有实测的层，状态必须写“未启用”或“未验证”。

## 世界书源文件最低要求

每个条目都要明示：

- strategy：常驻、关键词选择或目标版本支持的其他策略；
- keys：主要与次要触发词，常驻条目也要明确写空数组；
- position：插入位置、顺序，以及目标位置需要的角色或深度；
- recursion：是否允许被其他条目触发、是否触发其他条目、是否延迟递归；
- content：真正送入上下文的内容。

这些是源层语义，不代表本 Markdown 可直接导入。导出器仍须按 manifest 锁定的目标环境生成并验证。

## 发布门禁

- 静态检查只能证明文件结构可读，不能证明 SillyTavern 可用。
- 正式发布前必须在 manifest 指定的真实 SillyTavern 环境中导入。
- 至少回归：角色可导入、世界书可加载、触发符合预期、无意外常驻、首条消息正常、已声明扩展能初始化。
- 未执行真实导入时，必须写“未验证”，不得写“已兼容”。

## 完成标准

- [ ] manifest 已锁定目标 SillyTavern 和实际使用的扩展版本。
- [ ] 世界观与角色均能追溯到源文件。
- [ ] 派生 JSON、PNG、ZIP 未被当作真源。
- [ ] 对话调试有输入、预期、实际与结论。
- [ ] 正式发布前已完成真实 SillyTavern 导入回归。

## 常见错误

- 一开始就手写最终 JSON，之后不知道应该改哪一份。
- 把 Tavern Helper、EJS、MVU 当成 SillyTavern Core 自带能力。
- 沿用别的项目 JSON 字段映射，却没有核对目标版本。
- 用“高频/低频”代替真正的 keys。
- 静态检查通过就声称角色卡已在真实运行时验证。
