# 写回状态机

## 何时用

任何 Agent 生成的长期内容准备进入正式 Wiki、工具库、创意库或运维区时。

## 三步操作

1. 建候选：记录目标、来源、base_hash、差异和风险。
2. 审核批准：检查分类、冲突、秘密、链接与回滚。
3. 单 writer 提交并验证；失败进入 conflict 或 failed，不静默重试覆盖。

## 状态

~~~text
captured
  → classified
  → candidate
  → reviewed
  → approved
  → committing
  → verifying
  → published

任一步可进入 rejected
提交前哈希变化进入 conflict
写入或验证失败进入 failed
~~~

## 每个候选最低信息

- candidate_id；
- 目标路径；
- 来源或输入引用；
- knowledge_class；
- base_hash；
- 预览差异；
- 允许动作与禁止动作；
- 风险；
- 验证与回滚办法。

## 状态规则

- approved 只批准候选中列出的路径和差异，不授予全库权限。
- committing 期间由单 writer 持有提交权。
- verifying 失败时不得标 published。
- conflict 必须重新读取目标、人工或 reviewer 合并，再生成新 base_hash。
- rejected 和 failed 保留必要原因，不能把同一差异换名后绕过审批。

## 完成标准

- [ ] 正式内容可追溯到候选和批准。
- [ ] 哈希与差异已校验。
- [ ] 验证失败未发布。
- [ ] index 与 log 同步。

## 常见错误

- 审批一句“可以”就允许任意后续变化。
- 目标变化后仍使用旧 diff。
- 写完页面忘记 index 和 log。
