# 路径配置

## 何时用

第一次接入 Hermes、移动总仓，或准备把 LLMWiki 严格隔离时。

## 三步操作

1. 选择默认同根或高级严格隔离。
2. 使用绝对路径，检查目录真实存在。
3. 先用只读查询验证；只有配置真实强制边界后，才测试一个候选写入，不直接批量迁移。

## 方案 A：统一同根，当前默认

~~~text
AGENT_FOUNDRY_VAULT_HOME=<Agent Foundry Vault智能体工坊绝对路径>
OBSIDIAN_VAULT_PATH=<同一个 Agent Foundry Vault智能体工坊绝对路径>
WIKI_PATH=<同一个 Agent Foundry Vault智能体工坊绝对路径>
~~~

优点：

- 符合当前 SCHEMA：raw、concepts、entities、comparisons、queries 位于 Vault 根。
- Obsidian 和 Hermes 内置 LLMWiki 看到同一套 wikilink、index.md 与 log.md。
- 新手路径最少。

代价：

- AGENTS、权限规则、候选写回和单 writer 只提供治理约束，不自动成为 Hermes 的文件系统门禁。
- 同根不是沙箱；Hermes 进程如果拥有文件权限，技术上仍可能触及其他目录。默认只读/候选化，强制限制需 OS ACL、只读挂载、隔离 profile/container 或受限 adapter。

## 方案 B：严格隔离，高级迁移

目标形态示例：

~~~text
Agent Foundry Vault智能体工坊/ <- OBSIDIAN_VAULT_PATH
  wiki-runtime/               <- WIKI_PATH
    SCHEMA.md
    index.md
    log.md
    raw/
    concepts/
    entities/
    comparisons/
    queries/
~~~

优点：

- LLMWiki 的文件系统可写根更小。
- 更容易用独立账号、容器或 ACL 限制。

代价：

- 这不是改两个环境变量就完成。
- 必须重排当前根协议目录，并同步修改 SCHEMA、index、链接、验证脚本、同步范围和备份恢复步骤。
- 迁移前要生成链接清单、做 Vault 外备份、dry-run 和完整回归。

本仓当前不执行该重排。只有用户明确批准结构迁移后，才能进入 governed-write 流程。

## 路径检查

- 使用绝对路径，不依赖启动目录。
- Windows 路径含空格或中文时保留完整字符串，不手工拆分。
- 环境变量值放在 Vault 外，不把真实 .env 同步。
- `AGENT_FOUNDRY_VAULT_HOME` 应指向“Agent Foundry Vault智能体工坊”本身，不是上一级工作区。
- `WIKI_PATH` 不负责加载项目宪法；Hermes CLI 需从总仓根启动，Gateway/cron 需另行设置并验证各自工作目录，确保根 `AGENTS.md` 真正进入上下文。

## 完成标准

- [ ] 三个路径指向符合所选方案。
- [ ] Hermes 会话已从正确工作目录加载根 `AGENTS.md`。
- [ ] 默认方案下 LLMWiki 只做读取/候选；若开放自动提交，已单独验证技术强制边界。
- [ ] 高级方案没有在未迁移时提前切换。

## 常见错误

- 相对 external_dirs 随工作目录漂移。
- WIKI_PATH 指向子目录，但 raw 和 index 仍留在旧根。
- 把环境变量文件提交到 Vault。
