# 故障 Runbook

## 何时用

出现部分写入、同步冲突、断链、LLMWiki 越界、Skill 异常、误删或运行时不可用时。

## 三步操作

1. 停止扩大影响：暂停正式 writer，保留现场，必要时暂停传播错误的同步。
2. 在 Vault 外做现场快照，确定最后已知良好版本和受影响路径。
3. 恢复到候选状态，验证后逐步恢复 writer 与同步。

## 通用步骤

1. 记录事件开始时间、发现方式、影响范围和当前 owner。
2. 暂停写入；不要一边排错一边继续自动提交。
3. 复制当前 Vault 到外部临时恢复目录。
4. 检查临时文件、锁、最近 log、候选、同步历史和版本历史。
5. 选择恢复办法：完成原子提交、回滚、三方合并或从备份恢复。
6. 运行：

~~~powershell
node scripts/verify-repo.mjs
node scripts/harness-smoke.mjs
~~~

7. 涉及外部运行时的，再做真实运行时检查；静态通过不能替代。
8. 先恢复只读访问，再恢复候选生成，最后恢复单 writer 和同步。
9. 补事件、变更和复盘记录。

## 场景表

| 故障 | 先做什么 | 恢复重点 |
|---|---|---|
| 部分写入 | 停 writer，保留临时文件 | 核对原文件、临时文件和变更集 |
| 哈希冲突 | 转 conflict | 三方合并并重新审批 |
| 同步冲突 | 停 writer并做现场副本 | 不按时间戳盲选，检查两个版本 |
| LLMWiki 越界 | 撤销越界变更 | 审核 30、50、60、70 与治理文件 |
| raw 被覆盖 | 保留损坏副本 | 从不可变备份恢复旧快照，新增修订版 |
| external_dirs Skill 被改 | 暂停 Skill 管理 | 核对来源、权限、本地同名遮蔽和 bundle |
| Hermes 不可用 | Vault 降级为人工只读/编辑 | 队列保留，恢复后从 checkpoint 重跑 |
| Obsidian 不可用 | 用普通 Markdown 编辑器只读或谨慎编辑 | 不依赖插件才能恢复 |

## 恢复验证

- 仓库结构和 Frontmatter 可读；
- 无断链或新增断链有解释；
- index 与正式页面一致；
- log 只追加且没有秘密；
- raw 旧快照未改变；
- 正式写回能追溯到候选、批准和 base_hash；
- 若涉及 SillyTavern，完成真实导入回归；
- 若涉及 Hermes Skill 或 bundle，用真实 Hermes 列表、查看和调用验证。

## 完成标准

- [ ] 影响停止扩大。
- [ ] 恢复点和证据可定位。
- [ ] 静态与必要运行时验证均完成。
- [ ] writer 和同步按顺序恢复。
- [ ] 事件与防复发动作已记录。

## 常见错误

- 没做现场副本就开始修。
- 为了消除报错删除锁、日志或冲突版本。
- 静态校验通过就声称外部运行时恢复。
