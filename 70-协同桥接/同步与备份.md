# 同步与备份

## 何时用

准备多设备使用、启用无头同步、迁移 Vault 或做批量变更前。

## 三步操作

1. 选一个实时同步方案，并指定唯一提交主机。
2. 在 Vault 外做独立、带时间点的可恢复备份。
3. 小范围同步，检查冲突和恢复，再扩大使用。

## 同步原则

- 同一 Vault 只启用一个实时同步服务。
- 不让 Obsidian Sync、OneDrive、Dropbox 和自建双向同步同时争用。
- Git 可做版本历史的一部分，但不是实时协同锁，也不自动等于完整备份。
- 无头同步工具只有实际安装、登录和健康检查后才算启用。
- 同步服务复制文件，不判断内容正确性；错误删除也可能被快速同步。

## 备份原则

- 备份放 Vault 外，至少保留一个离线或不同故障域副本。
- 批量改动前先创建可识别的恢复点。
- 备份要覆盖 Markdown、附件和必要配置；密钥单独按秘密策略备份。
- 定期抽样恢复到临时目录，并运行仓库校验。

## 不同步内容

- 真实 Hermes HOME、MEMORY、USER 和状态数据库；
- .env、API Key、Cookie、令牌、私钥；
- 大体积 trace、模型请求响应、缓存；
- 临时锁与未完成的中间文件；
- 不需要跨设备的本机 UI 状态。

## 冲突处置

1. 暂停 Agent writer。
2. 在 Vault 外复制当前现场。
3. 比较两个版本及 base_hash，不按修改时间盲选。
4. 人工或 reviewer 合并为新候选。
5. 验证链接、index、log 和来源后恢复同步。

## 完成标准

- [ ] 只有一个实时同步方案。
- [ ] 有 Vault 外备份。
- [ ] 最近一次恢复演练成功。
- [ ] 秘密和大 trace 未同步。

## 常见错误

- 把同步历史当唯一备份。
- 两台 Hermes 主机同时直接写正式页。
- 从未恢复过，却声称备份可用。
