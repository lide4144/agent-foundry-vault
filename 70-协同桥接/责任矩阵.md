# 责任矩阵

## 何时用

不确定“谁能写哪一块”，或准备开放新工具权限时。

## 三步操作

1. 找到组件。
2. 核对真源、可写区和禁止区。
3. 若任务越界，改走候选写回或人工批准。

## 矩阵

| 组件 | 真正负责 | 默认可写 | 默认禁止 |
|---|---|---|---|
| 人类 / Obsidian | 阅读、编辑、链接、审批、解决冲突 | 经授权的 Vault 页面 | 自动批准 Agent 写回 |
| Hermes LLMWiki Skill | 来源摄入、派生知识、交叉链接、lint | raw 新快照、concepts、entities、comparisons、queries、index.md、log.md | 30、50、60、70、治理文件和秘密 |
| Hermes Runtime | 调 Skill、执行任务、排队、生成候选、报告验证 | 10-收件箱候选、被明确授权的运维摘要 | 把未审输出直接发布；复制完整记忆或大 trace |
| Agent Foundry Harness | 协议、任务、trace、评测、回放 | Harness 指定运行区与候选报告 | 直接修改正式 Wiki 和发布物 |
| 单 writer | 串行提交已批准变更 | 当前变更集指定路径 | 擅自扩大审批范围 |
| 同步服务 | 复制已提交文件 | 同步配置允许的文件 | 决定哪一版内容正确；替代备份 |
| 备份系统 | 保存可恢复历史 | Vault 外备份介质 | 参与实时编辑 |

## 所有权规则

- 内容真源由目录决定，不由“最后一次是谁写的”决定。
- 角色卡和世界书的真源在创意项目“04-源文件”，导出物不是真源。
- Hermes 真实 HOME、记忆、密钥和大 trace 在 Vault 外。
- 候选写回不等于发布；批准后仍要由单 writer 提交和验证。

## 完成标准

- [ ] 每个写动作能指出责任主体。
- [ ] 每个正式文件只有一个真源。
- [ ] 越界动作被拒绝或转候选。

## 常见错误

- 让同步服务解决内容冲突。
- 让 Runtime 记忆替代长期 Wiki。
- 让 Harness 分数自动批准正式写回。
