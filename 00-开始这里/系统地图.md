# 系统地图

本页只回答一个问题：内容应该先去哪。

## 何时用

新建文件前拿不准位置，或想理解 Obsidian、LLMWiki 与 Agent 运维之间的边界时。

## 三步判断

1. 未整理的内容先放 `10-收件箱/`。
2. 人能直接阅读和维护的正式内容，进入工具库或 Wiki 根目录保留区。
3. Agent 的运行状态、证据账本和自动化配置留在后台模块，不塞进新手笔记。

## 内容地图

| 位置 | 放什么 | 不放什么 |
|---|---|---|
| `00-开始这里/` | 入门、路线、术语、FAQ | 正式知识与运行日志 |
| `10-收件箱/` | 闪念、待整理资料、写回候选 | 已确认的长期知识 |
| [[20-Agent-Harness/README|`20-Agent-Harness/`]] | 任务协议、角色契约、三档工作流和离线回放训练 | 正式知识与未经批准的真实写入 |
| `30-系统工具库/` | SOP、规范、安全清单 | 某个具体知识实体 |
| `40-Wiki知识库/` | Wiki 使用说明与包装页 | LLMWiki 的正式条目文件 |
| 根目录 `raw/` | 原始来源与只读素材 | Agent 改写结果 |
| 根目录 `concepts/` | 定义、原理、术语 | 具体人物、软件、项目 |
| 根目录 `entities/` | 人物、软件、作品、组织等对象 | 抽象概念 |
| 根目录 `comparisons/` | 对比与冲突分析 | 未核对的单源摘录 |
| 根目录 `queries/` | 查询结果、待复核研究记录 | 无来源的确定性结论 |
| `templates/` | 四类通用成品模板 | 运行时 Prompt 与机器 Schema |
| `80-看板与索引/` | 手工看板、可选查询示例 | 事实正文 |
| `90-归档/` | 停用、废弃和旧版内容 | 仍在使用的内容 |

## 完成标准

- [ ] 能说出收件箱、工具库、Wiki 五个根目录各自的用途。
- [ ] 能解释“人类知识前台”和“Agent 运行后台”不是一回事。
- [ ] 不确定时会先收件，而不是随意创建新分类。

## 常见错误

- 把 `40-Wiki知识库/` 当作 LLMWiki 实际数据目录。
- 把 `raw/` 中的来源文件原地改写成总结。
- 把缓存、向量索引或 trace 当作唯一知识源。
- 为了目录整齐而批量移动尚未备份的文件。
