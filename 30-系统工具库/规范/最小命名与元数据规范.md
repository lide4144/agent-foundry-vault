# 最小命名与元数据规范

目标是让文件“看得懂、搜得到、不会因全局改名破坏局部规则”。

## 何时用

新建正式笔记、整理收件箱，或准备重命名文件时。

## 三步操作

1. **先读局部规则**：所在目录若有 README、AGENTS 或其他明确规则，以局部规则为准。
2. **起可读标题**：没有局部命名要求时，可用 `类别-明确中文名.md`，例如 `概念-原子笔记.md`。
3. **只填五字段**：`type / status / created / tags / source`；不会填的值可以留空，不擅自增加机器字段。

## 首周字段示例

```yaml
---
type: concept
status: candidate
created: 2026-07-17
tags:
  - 知识管理
source: "来源名称或本人想法"
---
```

## 命名检查

- 标题脱离目录后仍能理解。
- 不使用 `新建笔记`、`最终版2`、`未命名` 等失去语义的名称。
- 不把日期、状态、作者、版本全部堆进文件名；这些信息优先写正文或既有字段。
- 不批量重命名 `raw/`。
- 重命名前先检查同名文件、现有链接和局部规则。

## 完成标准

- [ ] 文件名清楚且不冲突。
- [ ] 只使用首周五字段。
- [ ] 来源可追溯。
- [ ] 没有违反更具体的仓库规则。

## 常见错误

- 把通用命名规范强行套到已有仓库。
- 用标签重复文件夹、状态和全部正文关键词。
- 把置信度、trace_id、token 等机器字段写进新手笔记。
- 未备份就批量改名。
