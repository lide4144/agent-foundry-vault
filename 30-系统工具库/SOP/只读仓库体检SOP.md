# 只读仓库体检 SOP

体检只发现问题并给证据，不自动修复、不改名、不搬移、不删除。

## 何时用

- 接手陌生仓库。
- 大改前想建立基线。
- 怀疑存在断链、重复、字段漂移或规则冲突。

## 三步总览

1. **确认边界**：记录仓库根、允许读取范围、禁止触碰目录和局部规则。
2. **只读检查**：查看目录、文件名、Frontmatter、链接、索引和日志，不执行写操作。
3. **报告发现**：按证据、影响、建议分级；修复另开任务并等待批准。

## 检查清单

- [ ] 仓库根目录与目标版本已确认。
- [ ] README、AGENTS、SCHEMA 或目录说明之间是否冲突。
- [ ] 是否存在未命名、重复或疑似同名异实体文件。
- [ ] 首周字段是否出现拼写分叉，例如 `created` 与 `create_date` 混用。
- [ ] 内部链接目标是否真实存在。
- [ ] `raw/` 是否保持只读和原始性。
- [ ] 正式知识变更是否同步维护 `index` 与 `log`。
- [ ] 是否有秘密、令牌或个人敏感信息误入普通笔记。

## 报告格式

每条发现只写四项：

1. 位置。
2. 证据。
3. 影响。
4. 建议动作与是否需要人工批准。

体检报告可先留在对话或单独审计草稿中；不要为了记录体检而修改被检查仓库。

## 完成标准

- [ ] 目标仓库内容零修改。
- [ ] 每项结论都有具体文件或规则证据。
- [ ] “确认问题”和“可能问题”明确区分。
- [ ] 修复建议没有被当场执行。

## 常见错误

- 看到明显错误就顺手修。
- 用全局规范否定局部宪法。
- 把格式偏好当成故障。
- 只汇报数量，不给具体位置和证据。
