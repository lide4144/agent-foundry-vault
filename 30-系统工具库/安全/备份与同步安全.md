# 备份与同步安全

同步负责让多设备看到相同状态；备份负责让你回到过去。两者不能互相替代。

## 何时用

- 第一次配置同步。
- 批量移动、改名、删除或写回前。
- 安装会执行脚本或系统命令的插件前。
- 更换电脑、同步服务或仓库位置时。

## 三步操作

1. **备份**：复制整个 Vault，包括 `.obsidian` 配置目录，并放到不参与同一实时同步的位置。
2. **验证**：打开备份中的几篇中文笔记和附件，确认能读取，并记录备份时间。
3. **再同步或修改**：主库尽量只使用一种实时同步方案；发生冲突先停止同步并保留两份副本。

## 安全清单

- [ ] 同步前已有独立备份。
- [ ] 备份包含笔记、附件和 `.obsidian`。
- [ ] Vault 内没有再嵌套另一个 Vault。
- [ ] 没有在同一主库叠加多个实时同步工具。
- [ ] 加密密码保存在可靠的密码管理位置。
- [ ] 社区插件来源可信，权限与副作用已理解。
- [ ] 秘密、API 令牌和账号凭据不写入普通 Markdown。

## 恢复演练

至少选一篇无敏感信息的测试笔记，确认能从备份副本找回。没有验证过恢复的“备份”只能算副本意图，不能算可用恢复方案。

## 完成标准

- [ ] 能说明最新备份在哪里、何时创建。
- [ ] 已实际验证至少一个文件能恢复。
- [ ] 知道发生同步冲突时先停止而不是继续覆盖。
- [ ] 高风险改动前能建立新的恢复点。

## 常见错误

- 把同步历史当作唯一备份。
- 只备份 `.md`，遗漏附件和配置。
- 两种同步工具同时监控同一主库。
- 从未做过恢复演练。
